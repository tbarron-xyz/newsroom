# attonews Data Storage Strategy

## Overview
This document outlines the Redis data storage strategy for the attonews application. All data will be stored in Redis using keys with structured naming conventions and appropriate data types for efficient access and querying.

## Data Types and Structures

### Editor
The editor is a single entity with bio, prompt, AI model configuration, and throttling settings.

**Keys:**
- `editor:bio` - String containing the editor's biography
- `editor:prompt` - String containing the editor's system prompt
- `ai:model_name` - String containing the default AI model name (legacy field)
- `editor:article_model_name` - String containing the model for article generation
- `editor:event_model_name` - String containing the model for event generation
- `editor:story_selection_model_name` - String containing the model for selecting stories for editions
- `editor:edition_selection_model_name` - String containing the model for selecting editions for daily edition
- `editor:chat_model_name` - String containing the model for chat interactions
- `editor:message_slice_count` - String containing message slice count for AI processing
- `editor:base_url` - String containing optional base URL for OpenAI API requests
- `article_generation:period_minutes` - String containing article generation period in minutes
- `article_generation:last_time` - String containing last article generation timestamp (milliseconds since epoch)
- `event_generation:period_minutes` - String containing event generation period in minutes
- `event_generation:last_time` - String containing last event generation timestamp (milliseconds since epoch)
- `edition_generation:period_minutes` - String containing edition generation period in minutes
- `edition_generation:last_time` - String containing last edition generation timestamp (milliseconds since epoch)

### Reporters
Reporters are stored with their beats, prompts, and enabled status. Each reporter has a unique ID.

**Keys:**
- `reporters` - Set containing all reporter IDs
- `reporter:{id}:beats` - Set containing the reporter's beat strings
- `reporter:{id}:prompt` - String containing the reporter's system prompt
- `reporter:{id}:enabled` - String ("true"/"false") indicating if reporter is enabled

### Articles
Articles are generated by reporters and stored with metadata including prompts and source messages.

**Keys:**
- `articles:{reporter_id}` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Article ID
- `articles:latest` - Global sorted set for latest articles (pruned to 100 entries)
- `article:{article_id}:headline` - String containing the article headline
- `article:{article_id}:body` - String containing the article body
- `article:{article_id}:time` - String containing the generation time (milliseconds since epoch)
- `article:{article_id}:prompt` - String containing the prompt used to generate the article
- `article:{article_id}:message_ids` - JSON string array of message IDs used as sources
- `article:{article_id}:message_texts` - JSON string array of message texts used as sources
- `article:{article_id}:message_dids` - JSON string array of Bluesky DIDs for source messages
- `article:{article_id}:message_rkeys` - JSON string array of Bluesky record keys for source messages
- `article:{article_id}:model_name` - String containing the AI model name used to generate the article
- `article:{article_id}:input_token_count` - String containing input token count
- `article:{article_id}:output_token_count` - String containing output token count
- `article:{article_id}:reporter_id` - String containing the reporter ID that generated the article

### Events
Events are generated by reporters and stored with facts and metadata.

**Keys:**
- `events:{reporter_id}` - Sorted set where:
  - Score: Created time (milliseconds since epoch)
  - Member: Event ID
- `events:latest` - Global sorted set for latest updated events (max 50 entries)
- `event:{event_id}:title` - String containing the event title
- `event:{event_id}:created_time` - String containing the creation time (milliseconds since epoch)
- `event:{event_id}:updated_time` - String containing the last update time (milliseconds since epoch)
- `event:{event_id}:facts` - JSON string array of event facts
- `event:{event_id}:where` - String containing where the event took place (optional)
- `event:{event_id}:when` - String containing date and time the event took place (optional)
- `event:{event_id}:message_ids` - JSON string array of message IDs used as sources
- `event:{event_id}:message_texts` - JSON string array of message texts used as sources
- `event:{event_id}:model_name` - String containing the AI model name used to generate the event
- `event:{event_id}:input_token_count` - String containing input token count
- `event:{event_id}:output_token_count` - String containing output token count
- `event:{event_id}:reporter_id` - String containing the reporter ID that generated the event

### Newspaper Editions
Newspaper editions are generated by the editor every 6 hours, containing selected articles.

**Keys:**
- `editions` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Edition ID
- `editions:latest` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Edition ID
  - NOTE: Automatically pruned to 25 most recent entries
- `edition:{edition_id}:stories` - Set containing article IDs included in this edition
- `edition:{edition_id}:time` - String containing the generation time (milliseconds since epoch)
- `edition:{edition_id}:prompt` - String containing the prompt used to generate the edition
- `edition:{edition_id}:model_name` - String containing the AI model name used to generate the edition
- `edition:{edition_id}:input_token_count` - String containing input token count
- `edition:{edition_id}:output_token_count` - String containing output token count

### Daily Editions
Daily editions are generated by the editor every 24 hours, containing selected newspaper editions and detailed content.

**Keys:**
- `daily_editions` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Daily Edition ID
- `daily_edition:{daily_edition_id}:editions` - Set containing edition IDs included in this daily edition
- `daily_edition:{daily_edition_id}:time` - String containing the generation time (milliseconds since epoch)
- `daily_edition:{daily_edition_id}:front_page_headline` - String containing front page headline
- `daily_edition:{daily_edition_id}:front_page_article` - String containing front page article
- `daily_edition:{daily_edition_id}:newspaper_name` - String containing newspaper name
- `daily_edition:{daily_edition_id}:model_feedback_positive` - String containing positive model feedback about the prompt
- `daily_edition:{daily_edition_id}:model_feedback_negative` - String containing negative model feedback about the prompt
- `daily_edition:{daily_edition_id}:topics` - JSON string containing topics array with detailed news stories
- `daily_edition:{daily_edition_id}:prompt` - String containing the prompt used to generate the daily edition
- `daily_edition:{daily_edition_id}:model_name` - String containing the AI model name used to generate the daily edition
- `daily_edition:{daily_edition_id}:input_token_count` - String containing input token count
- `daily_edition:{daily_edition_id}:output_token_count` - String containing output token count

### Users
Users are stored with authentication and role information.

**Keys:**
- `users` - Set containing all user IDs
- `user:{user_id}:email` - String containing user email
- `user:{user_id}:password_hash` - String containing hashed password
- `user:{user_id}:role` - String containing user role ("admin"/"editor"/"reporter"/"user")
- `user:{user_id}:created_at` - String containing creation timestamp (milliseconds since epoch)
- `user:{user_id}:last_login_at` - String containing last login timestamp (milliseconds since epoch)
- `user:{user_id}:has_reader` - String ("true"/"false") indicating reader access permission
- `user:{user_id}:has_reporter` - String ("true"/"false") indicating reporter access permission
- `user:{user_id}:has_editor` - String ("true"/"false") indicating editor access permission
- `user_by_email:{email}` - String containing user ID for email lookup

### KPIs
Key Performance Indicators are stored to track AI API usage and costs.

**Keys:**
- `kpi:{name}:value` - String containing the current KPI value (numbers stored as strings)
- `kpi:{name}:last_updated` - String containing timestamp of last update (milliseconds since epoch)

**KPI Names:**
- `Total AI API spend` - Total cost spent on AI API calls
- `Total text input tokens` - Total number of input tokens used
- `Total text output tokens` - Total number of output tokens used

### Job Status
Job status tracking is used to monitor the execution state of background jobs (article generation, newspaper edition creation, daily edition compilation).

**Keys:**
- `job:{job_name}:running` - String ("true"/"false") indicating if job is currently running
- `job:{job_name}:last_run` - String containing last run timestamp (milliseconds since epoch)
- `job:{job_name}:last_success` - String containing last successful run timestamp (milliseconds since epoch)

**Job Names:**
- `reporter` - Article generation job
- `daily` - Daily edition compilation job
- `newspaper` - Newspaper edition generation job (uses `reporter` job for tracking)

### Forum
The forum provides a discussion platform with sections, forums, threads, and posts.

**Keys:**
- `forum:sections` - JSON string array of forum sections
- `forum:{forumId}:threads` - Sorted set where:
  - Score: Creation time (milliseconds since epoch)
  - Member: Thread ID
- `forum:{forumId}:counter` - Hash containing thread and post counts (fields: `threadCount`, `postCount`)
- `forum:next_thread_id` - String containing next available thread ID (auto-incrementing counter)
- `forum:next_post_id` - String containing next available post ID
- `forum:thread:{threadId}` - Hash containing thread details (fields: `id`, `title`, `forumId`, `author`, `createdAt`, `replyCount`, `lastReplyTime`)
- `forum:thread:{threadId}:posts` - Sorted set where:
  - Score: Creation time (milliseconds since epoch)
  - Member: Post ID
- `forum:thread:{threadId}:post:{postId}` - JSON string containing post details (id, content, author, createdAt)

### Homepage Chat
Homepage chat messages are stored for the global IRC-style chat on the home page.

**Keys:**
- `homepage_chat:messages` - Sorted set where:
  - Score: Timestamp (milliseconds since epoch)
  - Member: Message ID
  - NOTE: Automatically pruned to 100 most recent entries
- `homepage_chat:{id}:sender_name` - String containing the sender display name
- `homepage_chat:{id}:content` - String containing the message text
- `homepage_chat:{id}:timestamp` - String containing timestamp (milliseconds since epoch)
- `homepage_chat:{id}:type` - String containing message type ("user" or "assistant")

### Artifacts
Artifacts are reusable AI processing nodes with prompts, inputs, and output schemas for the flow editor.

**Keys:**
- `artifact:latest` - Sorted set where:
  - Score: Generated at time (milliseconds since epoch)
  - Member: Artifact ID
- `artifact:{type}` - Sorted set where:
  - Score: Generated at time (milliseconds since epoch)
  - Member: Artifact ID
  - NOTE: Per-type index (e.g., `artifact:event`, `artifact:article`)
- `artifact:{id}:type` - String containing the artifact type (e.g., "event", "article", "edition")
- `artifact:{id}:inputs` - JSON string array of input definitions (name, source, type, filter)
- `artifact:{id}:prompt_system` - String containing the system prompt
- `artifact:{id}:prompt_user_template` - String containing the user prompt template
- `artifact:{id}:output` - JSON string containing the generated output (optional)
- `artifact:{id}:metadata` - JSON string containing status, generated_at, reporterId

### Personas
Personas are used for dynamic opinion article generation.

**Keys:**
- `personas:dynamic:latest` - String containing JSON array of dynamic personas, set with TTL (24h default)
- `personas:classic` - String containing classic personas (unused/legacy)

### Opinion Articles
Opinion articles are generated by AI personas, providing editorial-style content.

**Keys:**
- `opinions:latest` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Opinion Article ID
  - NOTE: Automatically pruned to 50 most recent entries
- `opinion:{id}:persona` - String containing the persona type/enum used
- `opinion:{id}:headline` - String containing the article headline
- `opinion:{id}:content` - String containing the article body/content
- `opinion:{id}:time` - String containing the generation time (milliseconds since epoch)
- `opinion:{id}:article_ids` - JSON string array of article IDs referenced
- `opinion:{id}:model_name` - String containing the AI model name used
- `opinion:{id}:input_token_count` - String containing input token count
- `opinion:{id}:output_token_count` - String containing output token count

### Ticker
The ticker provides a scrolling news ticker with the latest daily edition summary.

**Keys:**
- `ticker:latest` - Hash containing fields: `id`, `text`, `generationTime`, `dailyEditionId`, `modelName`, `inputTokenCount`, `outputTokenCount`

### Chat Session
Chat sessions store temporary AI chat state.

**Keys:**
- `chat:session:{id}` - String containing JSON chat session data, set with TTL (1800s default)

### App Logs
Application logs for monitoring and debugging.

**Keys:**
- `app:logs` - Sorted set where:
  - Score: Timestamp (milliseconds since epoch)
  - Member: Log entry
  - NOTE: Automatically pruned to 500 most recent entries

### Prism
Prism stores daily edition pairs for the prism display feature.

**Keys:**
- `prism_daily_editions` - Sorted set where:
  - Score: Generation time (milliseconds since epoch)
  - Member: Prism edition ID
  - NOTE: Automatically pruned to 10 most recent entries
- `prism_daily_edition:{id}:data` - String containing JSON prism data

## Key Naming Conventions
- Use colons (`:`) as separators for hierarchical key names
- Use descriptive prefixes (`editor:`, `reporter:`, `article:`, `edition:`, `daily_edition:`, `event:`, `user:`, `ai:`, `job:`, `kpi:`, `forum:`, `artifact:`, `homepage_chat:`, `opinion:`, `personas:`, `ticker:`, `chat:`, `app:`, `prism:`)
- Include IDs in curly braces for dynamic key generation
- Use consistent data types (Strings for text, Hashes for structured records, Sets for collections, Sorted Sets for time-ordered data)
- Use reverse lookup patterns like `user_by_email:{email}` for efficient lookups by non-ID fields
- Store JSON data as strings for complex objects (facts arrays, topics arrays, message arrays)

## Data Access Patterns
- **Editor lookup**: Direct key access with `GET editor:bio`, `GET editor:prompt`, and other editor configuration keys
- **Reporter enumeration**: `SMEMBERS reporters` to get all reporter IDs
- **Reporter details**: Direct key access with `SMEMBERS reporter:{id}:beats`, `GET reporter:{id}:prompt`, and `GET reporter:{id}:enabled`
- **Recent articles by reporter**: `ZREVRANGE articles:{reporter_id} 0 -1 WITHSCORES` for most recent articles
- **Latest articles (global)**: `ZREVRANGE articles:latest 0 -1 WITHSCORES` for most recent articles across all reporters
- **Articles in time range**: `ZRANGEBYSCORE articles:{reporter_id} {start_time} {end_time}`
- **Article details**: Direct key access with `GET article:{article_id}:headline`, `GET article:{article_id}:body`, etc.
- **Recent events by reporter**: `ZREVRANGE events:{reporter_id} 0 -1 WITHSCORES` for most recent events
- **Latest events (global)**: `ZREVRANGE events:latest 0 -1 WITHSCORES` for most recently updated events
- **Event details**: Direct key access with `GET event:{event_id}:title`, `GET event:{event_id}:facts`, etc.
- **Edition lookup**: `ZREVRANGE editions 0 -1 WITHSCORES` for most recent editions
- **Edition details**: `SMEMBERS edition:{edition_id}:stories` for articles in edition
- **Daily edition lookup**: `ZREVRANGE daily_editions 0 -1 WITHSCORES` for most recent daily editions
- **Daily edition details**: `SMEMBERS daily_edition:{daily_edition_id}:editions` for editions in daily edition; `GET daily_edition:{id}:front_page_headline`, `GET daily_edition:{id}:front_page_article`, `GET daily_edition:{id}:newspaper_name`, `GET daily_edition:{id}:topics` for display content
- **User enumeration**: `SMEMBERS users` to get all user IDs
- **User lookup by email**: `GET user_by_email:{email}` to get user ID
- **User details**: Direct key access with `GET user:{user_id}:email`, `GET user:{user_id}:role`, etc.
- **Job status lookup**: `GET job:{job_name}:running`, `GET job:{job_name}:last_run`, `GET job:{job_name}:last_success` for current job status
- **Forum sections**: `GET forum:sections` to get all forum sections with nested forums
- **Forum threads**: `ZREVRANGE forum:{forumId}:threads 0 -1 WITHSCORES` for threads in a forum
- **Forum counter**: `HGETALL forum:{forumId}:counter` to get thread and post counts
- **Thread details**: `HGETALL forum:thread:{threadId}` to get thread metadata
- **Thread posts**: `ZREVRANGE forum:thread:{threadId}:posts 0 -1 WITHSCORES` for posts in a thread
- **Post details**: `GET forum:thread:{threadId}:post:{postId}` to get a specific post
- **KPI lookup**: `GET kpi:{name}:value`, `GET kpi:{name}:last_updated` for KPI values
- **Artifact lookup**: `ZREVRANGE artifact:latest 0 -1 WITHSCORES` for most recent artifacts; `ZREVRANGE artifact:{type} 0 -1 WITHSCORES` for artifacts by type
- **Artifact details**: Direct key access with `GET artifact:{id}:type`, `GET artifact:{id}:inputs`, `GET artifact:{id}:prompt_system`, `GET artifact:{id}:prompt_user_template`, `GET artifact:{id}:output`, `GET artifact:{id}:metadata`
- **Opinion lookup**: `ZREVRANGE opinions:latest 0 -1 WITHSCORES` for most recent opinion articles
- **Opinion details**: Direct key access with `GET opinion:{id}:persona`, `GET opinion:{id}:headline`, `GET opinion:{id}:content`, etc.
- **Ticker**: `HGETALL ticker:latest` for current ticker data
- **Chat session**: `GET chat:session:{id}` for AI chat session state
- **Prism lookup**: `ZREVRANGE prism_daily_editions 0 -1 WITHSCORES` for prism pairs
- **Personas**: `GET personas:dynamic:latest` for dynamic persona list

## Performance Considerations
- Use connection pooling for Redis connections
- Implement proper error handling for Redis operations
- Consider using Redis pipelines for batch operations
- Monitor memory usage as data accumulates over time
- Implement data cleanup strategies for old articles/editions if needed
- Job status keys are lightweight and frequently accessed - consider caching in application layer if needed
- The `articles:latest` key is automatically pruned to 100 entries to prevent unbounded growth
- The `events:latest` key is automatically pruned to 50 entries to prevent unbounded growth
- The `editions:latest` key is automatically pruned to 25 entries to prevent unbounded growth
- The `homepage_chat:messages` key is automatically pruned to 100 entries
- The `opinions:latest` key is automatically pruned to 50 entries
- The `app:logs` key is automatically pruned to 500 entries
- The `prism_daily_editions` key is automatically pruned to 10 entries
- The `personas:dynamic:latest` key is set with a TTL (24h default)
- Chat sessions (`chat:session:{id}`) are set with a TTL (1800s default)

## Data Persistence
- Configure Redis persistence (RDB or AOF) based on data criticality requirements
- Consider backup strategies for Redis data
- Plan for data migration if schema changes are needed

## Security
- Use Redis authentication with username/password as specified
- Implement proper access controls
- Encrypt sensitive data if required
- Monitor Redis access logs for security

This strategy provides efficient storage and retrieval of all newsroom data while maintaining clear organization and scalability.
